# Acceptance Criteria
# 验收标准

## 一、系统功能验收

### AC-01 用户与标签基础能力
- 可以成功创建和查询用户
- 可以为用户设置标签
- 标签关系可持久化存储

### AC-02 画像生成
- 能为用户生成兴趣画像
- 画像中包含标签及对应权重
- 画像生成逻辑包含改进 TF-IDF 和时间衰减

### AC-03 候选召回
- 能基于目标用户标签快速召回候选用户
- 候选集不包含用户自身
- 候选集数量和逻辑符合设定规则

### AC-04 排序与重排
- 能基于相似度完成基础排序
- 能在基础排序之上执行规则重排
- 能输出最终 Top-K 推荐结果

### AC-05 推荐解释
- 每条推荐结果都有至少一条可读解释
- 解释中包含与排序有关的证据项
- 解释与排序逻辑不冲突

### AC-06 反馈更新
- 能记录用户对推荐对象的反馈
- 反馈能触发画像相关标签权重的轻量调整
- 更新后的画像可参与后续推荐

## 二、工程实现验收

### AC-07 工程结构
- 项目具备清晰的 controller / service / mapper / domain 分层
- 核心模块命名明确
- 配置、异常、返回结构规范

### AC-08 数据设计
- MySQL 表结构完整
- Redis Key 设计合理
- 推荐、解释、反馈数据可追溯

## 三、论文一致性验收

### AC-09 一致性
- 论文中描述的推荐流程与代码实现一致
- 论文中描述的数据表与系统实际表结构一致
- 论文中的解释机制与系统实际实现一致

### AC-10 数据与指标规范
- 实验数据来源明确
- 若使用模拟数据，论文中明确说明
- 指标定义明确，不虚构复杂实验结论

## 四、展示与答辩验收

### AC-11 可演示性
- 可以展示一次完整推荐流程
- 可以展示某个用户的推荐结果与解释
- 可以展示一次反馈更新前后推荐变化示例

### AC-12 文档完整性
- 项目方案、系统设计、数据库设计、接口设计、测试文档、论文初稿齐全
