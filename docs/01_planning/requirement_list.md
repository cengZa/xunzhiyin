# Requirement List
# 需求清单

## 一、功能需求

### FR-01 用户管理
系统应支持创建、查询和维护用户基础信息，包括姓名/昵称、年级、专业、社团等字段。

### FR-02 标签管理
系统应支持标签的创建、分类、维护以及用户标签选择关系的记录。

### FR-03 用户画像生成
系统应根据用户标签数据，计算用户兴趣画像，并生成可用于推荐的特征向量。

### FR-04 改进 TF-IDF 权重计算
系统应支持在传统 TF-IDF 基础上增加标签区分度调节、时间衰减和 Top-K 机制。

### FR-05 倒排召回
系统应支持通过标签—用户倒排索引结构快速召回候选用户集合。

### FR-06 相似度排序
系统应支持使用余弦相似度对候选用户进行排序。

### FR-07 规则重排
系统应支持结合校园场景规则对排序结果进行再次调整，例如年级差限制、专业相关性优先、社团重合加权等。

### FR-08 推荐结果输出
系统应支持为指定用户输出 Top-K 推荐列表。

### FR-09 解释生成
系统应支持为每条推荐结果生成推荐原因，且解释必须能映射到排序贡献项。

### FR-10 反馈采集
系统应支持记录用户对推荐结果的反馈，包括关注、忽略等。

### FR-11 反馈更新
系统应支持根据反馈结果轻量更新画像中相关标签权重。

### FR-12 推荐记录持久化
系统应支持保存推荐结果、解释内容和反馈数据，便于后续分析与论文展示。

## 二、非功能需求

### NFR-01 可实现性
系统设计必须适合本科工程项目实现，不依赖复杂基础设施。

### NFR-02 可维护性
模块边界清晰，代码分层规范，便于后续扩展。

### NFR-03 可解释性
推荐结果应具备清晰、可追溯、可说明的推荐依据。

### NFR-04 可验证性
系统应支持通过模拟数据与测试用例验证功能正确性与推荐逻辑合理性。

### NFR-05 性能可接受
在小规模校园数据场景下，推荐接口应保持可接受响应时间。

### NFR-06 一致性
论文、设计、实现、测试四者必须保持一致。

## 三、数据需求

1. 用户基础信息数据
2. 用户标签数据
3. 标签分类数据
4. 推荐结果数据
5. 推荐解释数据
6. 用户反馈数据

## 四、测试需求

1. 画像生成正确性测试
2. 候选召回有效性测试
3. 排序结果合理性测试
4. 重排规则生效测试
5. 解释与排序一致性测试
6. 反馈更新有效性测试
