# Risk List
# 风险清单

## 一、需求与边界风险

### R-01 需求层被演示层挤压
- 风险：演示首页、故事线接口、导出矩阵等答辩增强项占用过多注意力，导致 agent 高估其优先级。
- 影响：偏离开题报告中的核心交付主轴。
- 缓解：
  - 优先实现与验证画像、召回、排序、重排、解释、反馈主链路
  - 将演示增强项明确标注为答辩服务能力

### R-02 论文与实现边界漂移
- 风险：论文写作时把未实现能力、未验证指标或演示型结果写成正式结论。
- 影响：论文失真，答辩风险升高。
- 缓解：
  - 所有论文化表述必须回链到实现或验证文档
  - 代理指标与真实用户研究必须显式区分

## 二、数据与实验风险

### R-03 实验数据来源不充分
- 风险：当前更多依赖 mock 数据，难以支撑开题报告中的人工标注、问卷满意度等目标。
- 影响：论文量化目标难以完整闭环。
- 缓解：
  - 明确哪些结果来自模拟数据
  - 为真实标注、问卷或代理验证分别建说明页

### R-04 指标与目标不对齐
- 风险：仓库当前以治理检查、离线摘要和代理指标为主，而开题报告还包含 `Precision@10`、召回覆盖率、问卷理解度等目标。
- 影响：无法证明“研究目标 -> 验证方法 -> 结果评价”一致。
- 缓解：
  - 在验收标准中显式区分工程验收指标与论文量化目标
  - 在测试文档中注明哪些指标已落地，哪些仍需补充

## 三、算法与解释风险

### R-05 热门标签抑制不足
- 风险：改进 TF-IDF 若未有效压制高频标签，画像区分度会下降。
- 影响：召回与排序效果不稳定。
- 缓解：
  - 保留标签区分度与时间衰减设计
  - 在评估文档中记录标签权重变化和解释样例

### R-06 重排规则过强导致多样性下降
- 风险：年级、专业、社团规则权重过高时，可能压制原始兴趣相似度。
- 影响：推荐结果变得机械，难以支撑“合理匹配”叙事。
- 缓解：
  - 在参数实验中记录不同 `rerankWeightScale`
  - 论文中说明规则重排的收益与副作用

### R-07 解释与排序证据脱节
- 风险：解释文本如果未严格来自贡献项与规则命中，会形成“黑盒包装”。
- 影响：违背开题报告中的内生可解释目标。
- 缓解：
  - 解释生成必须读取排序贡献项与重排命中记录
  - 在测试中保留解释一致性检查

### R-08 反馈更新不稳定
- 风险：噪声反馈可能导致标签权重剧烈波动。
- 影响：后续推荐结果不稳定，难以证明反馈机制有效。
- 缓解：
  - 保持轻量更新策略
  - 在论文中明确反馈更新的边界，不夸大在线学习能力

## 四、工程与环境风险

### R-09 本地环境与文档基线不一致
- 风险：Java、MySQL、Redis 或脚本环境未按文档要求配置。
- 影响：治理检查、集成测试、答辩演示结果不稳定。
- 缓解：
  - 固定 Java 21 基线
  - 保留本地联调脚本与环境变量说明

### R-10 文档索引失真
- 风险：开题报告、需求层、thesis 层、测试层更新不同步。
- 影响：agent 会基于过期文档继续工作。
- 缓解：
  - 需求变化先更新 `docs/`
  - 复杂任务必须在 `exec-plans/` 落盘
  - 新增桥接文档统一收口论文入口

## 五、进度风险

### R-11 实验验证与论文修改时间被压缩
- 风险：按开题报告里程碑，系统联调、性能优化、论文撰写与答辩准备时间紧凑。
- 影响：后期容易只做展示，不足以支撑论文质量。
- 缓解：
  - 优先补“需求-验证-结果”闭环
  - 论文层优先写事实性章节，再修语言与格式
