# Recall Design
# 倒排召回实现设计

## 1. 目标

在全体用户中快速筛选出与目标用户存在标签交集的候选集合，降低排序阶段计算规模。

## 2. 输入

- 目标用户画像中的 Top-K 标签

## 3. Redis Key

- recall:inv:tag:{tagId} -> Set<userId>

## 4. 召回流程

### Step 1：读取目标用户画像
从 ProfileService 获取 UserProfileModel。

### Step 2：提取 Top-K 标签
只使用权重最高的 K 个标签进行召回，降低噪声与计算量。

### Step 3：查询倒排集合
遍历每个 tagId，读取 Redis Set。

### Step 4：合并候选池
做并集聚合，并记录每个候选与多少个目标标签相交。

### Step 5：候选过滤
过滤条件：
- 过滤自己
- 过滤 status != 1 的用户
- 可选过滤空画像用户

### Step 6：粗排（可选）
按“公共标签数”降序排序，截断前 N 个候选再进入正式排序。

## 5. 输出

- Set<Long> candidateUserIds

## 6. 复杂度说明

如果直接全量排序，复杂度近似 O(U)；
使用倒排召回后，复杂度主要取决于 Top-K 标签命中的候选集大小，在校园小规模场景下可明显降低排序规模。

## 7. 风险点

1. 热门标签倒排集合过大
2. Top-K 太大导致召回噪声过多
3. 标签同步漏更导致召回不准

## 8. 对策

1. 热门标签可适度降权，并在召回层限制参与范围
2. K 先取 5~10
3. 标签更新后统一触发倒排维护
