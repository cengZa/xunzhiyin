# 第 5 章 校园社交匹配推荐系统详细设计与实现

本章在概要设计的基础上，围绕校园社交匹配推荐系统的核心业务链路说明详细设计与实现。系统实现重点在于说明各模块如何协作完成“用户标签 -> 用户画像 -> 候选召回 -> 相似度排序 -> 校园规则重排 -> 推荐解释 -> 用户反馈 -> 画像更新”的闭环。

## 5.1 推荐主链路总体实现

系统推荐主链路以推荐服务为统一编排入口。一次推荐请求进入系统后，服务层先获取请求用户画像，再根据画像中的核心标签召回候选用户；随后对候选用户进行相似度排序，在基础排序结果上叠加校园场景规则、可信连接分和轻量探索机制；最后生成推荐解释、保存推荐结果并返回给用户。

系统核心类关系可用类图表示。推荐编排类位于主链路中心，向下依赖画像、召回、排序、重排、可信连接、探索、解释和持久化组件。该类关系明确了推荐流程的协作边界，也为画像生成、候选召回、排序重排和解释生成的独立测试提供依据。

## 5.2 用户与标签模块详细设计与实现

用户与标签模块是推荐链路的数据入口。用户数据提供年级、专业、学院、个人简介等校园上下文，标签数据提供学习兴趣、社团活动和兴趣偏好等推荐依据。用户与标签之间通过关系数据建立关联，关系中保留标签来源、选择时间和权重种子，为画像计算提供原始输入。

该模块的业务流程分为三步：第一，用户维护个人基础信息；第二，用户选择或更新标签；第三，系统保存用户标签关系，并在后续画像生成或推荐请求中使用这些关系。标签维护逻辑与推荐编排逻辑保持解耦，避免标签变更直接侵入推荐主流程。

从实现角度看，用户与标签模块不需要在论文中展开每个接口细节。论文重点应说明：用户属性为校园规则重排提供依据，标签关系为画像生成提供依据，标签更新时间为时间衰减提供依据。这样能够把用户与标签模块自然连接到后续画像模块。

用户标签维护过程不单独绘制时序图。该流程属于画像生成前的数据准备环节，正文说明即可支撑后续画像模块，避免在第 5 章中重复展开非核心交互。

## 5.3 用户画像模块详细设计与实现

用户画像模块负责把离散标签关系转换为标签权重向量。画像结果既用于召回和排序，也用于推荐解释，因此画像不能只保存标签列表，还需要保存标签权重、Top-K 核心标签和画像版本。

画像构建流程如下：

1. 读取用户标签关系、标签类型、选择时间和权重种子。
2. 计算标签在当前用户画像中的 TF 权重。
3. 计算或预留标签全局区分度 IDF。
4. 根据标签选择时间计算时间衰减因子。
5. 生成标签权重向量，并按权重降序截取 Top-K 核心标签。
6. 保存画像 JSON 和 Top-K JSON。
7. 按需写入画像缓存，减少后续推荐请求的重复计算。

> 图 5-4 用户画像生成时序图

系统采用改进 TF-IDF 构建画像。设用户 u 的标签集合为 T_u，标签 t 的权重为 w(u,t)，当前权重按式（5-1）计算：

公式（5-1）：w(u,t) = tf(u,t) × idf(t) × decay(t) × seed(u,t)。

其中，tf(u,t) 表示标签在用户标签集合中的相对频次，idf(t) 表示标签的全局区分度，seed(u,t) 表示标签关系中的原始权重种子。当前实现中，idf(t) 暂固定为 1.0，保留该项是为了后续接入全局标签分布统计。

时间衰减因子按式（5-2）计算：

公式（5-2）：decay(t) = exp(-lambda × days(t))。

其中，days(t) 表示标签选择时间距当前时间的天数，lambda 为衰减系数，当前实现取 0.02。画像构建完成后，系统按标签权重降序选取 Top-K 标签，作为候选召回和推荐解释的主要依据。

画像模块采用该设计的原因在于，校园标签中容易出现“学习”“运动”“音乐”等热门标签。如果只统计标签重合，热门标签会放大用户之间的表面相似性。改进 TF-IDF、时间衰减和 Top-K 裁剪可以在保持实现轻量的同时，提高画像区分度和解释可读性。

## 5.4 候选召回与相似度排序模块详细设计与实现

候选召回模块负责把推荐计算范围从全量用户缩小到候选用户集合。系统为标签维护倒排索引，即一个标签对应拥有该标签的一组用户。推荐时，系统读取请求用户画像中的 Top-K 标签，分别查询这些标签对应的用户集合，再对集合进行合并、去重和自身过滤，得到候选用户集合。

召回流程的关键是保留候选用户与目标用户之间的公共标签信息。这些公共标签既影响后续排序，也会进入解释模块，成为推荐理由的一部分。

排序模块在候选集合上计算用户画像之间的余弦相似度。设请求用户画像向量为 P_u，候选用户画像向量为 P_v，基础兴趣相似度按式（5-3）计算：

公式（5-3）：sim(u,v) = (P_u · P_v) / (||P_u|| × ||P_v||)。

当某一方画像为空或向量范数为 0 时，系统将相似度置为 0，避免无效计算。排序过程中，系统记录共同标签及其贡献值，形成标签贡献项。标签贡献项不仅用于计算推荐分数，也用于后续解释“哪些标签影响了推荐排序”。

## 5.5 校园规则重排、可信连接分与探索机制实现

基础排序主要体现兴趣相似性，但校园社交匹配还需要考虑年级、专业、社团和场景目标。系统在基础排序结果上加入校园规则重排，使推荐结果更符合不同场景下的匹配需求。

当前重排规则包括年级差、专业相关性和社团重合等。学习搭子场景更关注学习标签和专业相关性；社团搭子场景更关注社团重合和校园活动联系；兴趣同频场景更关注兴趣相似度，并允许保留少量探索位。

系统将基础兴趣分、校园规则分和可信连接分组合为最终分数。设基础兴趣分为 S_i，校园规则分为 S_c，可信连接分为 S_t，可信连接权重为 alpha，最终分数按式（5-4）计算：

公式（5-4）：S_final = S_i + S_c + alpha × S_t。

校园规则分由多个规则贡献累加得到，如式（5-5）所示：

公式（5-5）：S_c = sum(baseRuleScore_r × scenarioMultiplier_r × scale)。

可信连接分用于抑制资料过少或证据较弱的候选对象。系统不仅返回可信连接分，还返回可信原因，使最终推荐结果既有分数，也有可解释依据。

轻量探索机制主要用于兴趣同频场景。在不破坏前几名主结果稳定性的前提下，系统保留少量具有潜在兴趣关联的候选对象。该机制属于工程上的规则化设计，用于提高推荐列表的覆盖范围和场景适应性。

## 5.6 推荐解释生成与反馈更新实现

推荐解释模块负责把推荐计算过程中的证据转化为用户可理解的推荐理由。解释的输入来自三类证据：排序阶段的标签贡献项、重排阶段的规则命中和可信连接原因。系统先提取结构化证据，再根据模板生成规则解释文本。

为提高解释文本的可读性，系统保留外部大语言模型润色能力。当外部服务可用时，系统对规则解释进行语言润色；当密钥缺失、调用失败、超时或返回内容无效时，系统回退到规则解释。大语言模型只处理解释文本，不参与召回、排序、重排、可信连接分和反馈更新。

> 图 5-7 推荐解释证据流图

反馈模块用于形成推荐闭环。用户可以对推荐对象提交关注或忽略反馈。系统保存反馈记录，并根据推荐解释中的主要贡献标签对请求用户画像进行轻量调整。这样可以形成“推荐结果 -> 用户反馈 -> 画像调整 -> 下一轮推荐变化”的机制闭环。

> 图 5-8 反馈更新时序图

反馈更新的实现目标是使用户行为能够影响后续画像。系统通过保存反馈记录、提取推荐证据标签并调整画像权重，形成从推荐结果到画像更新的闭环。

## 5.7 本章小结

本章围绕校园社交匹配推荐系统的详细设计与实现进行了说明。系统以推荐主链路为核心，通过用户与标签模块提供数据入口，通过画像模块生成用户兴趣向量，通过倒排召回和相似度排序完成候选筛选，通过校园规则重排、可信连接分和轻量探索机制优化推荐结果，并通过解释生成和反馈更新形成可追溯闭环。

本章结合业务流程图、类图和时序图说明了核心模块的协作关系。上述设计围绕推荐主链路展开，为后续系统测试、推荐结果分析和功能验证提供依据。
