# 2026-03-27 Harness Reorg

## 背景
用户要求参考 OpenAI《Harness engineering》一文，重组本项目文档体系与 agent 壳子。

## 目标
- 建立短 `AGENTS.md`
- 建立 `docs/` 索引层
- 把原有长 prompt 改写为 shell
- 为后续 agent 工作提供稳定导航入口

## 范围内
- 新增导航与规范文档
- 重写 `docs/06_prompt/` 主要 prompt 文件
- 新增执行计划、质量、可靠性、安全等控制面文档

## 范围外
- 不重写既有设计细节内容
- 不迁移全部 numbered docs 到新目录
- 不引入新的自动化 lint 或 CI

## 执行步骤
1. 建立根入口与顶层架构图
2. 建立 docs 索引层
3. 改写 agent shell
4. 记录当前质量与技术债
5. 增加基础文档检查脚本与运维说明
6. 增加后端骨架一致性检查
7. 增加 service 核心签名检查
8. 增加 controller 主路由检查
9. 增加关键 API 字段检查与统一检查入口
10. 增加顶层模块边界检查

## 风险
- 新旧文档双轨并行期间可能出现入口混乱
- 未建立自动检查前，索引新鲜度需要人工维护

## 验收标准
- 根目录有可用 `AGENTS.md`
- `docs/README.md` 能导航到主要内容
- `docs/06_prompt/` 为短壳而非长百科
- 新增计划与质量文档已落盘
- 文档、后端骨架、模块边界、service 核心签名、controller 主路由、关键 API 字段有基础机械检查
- 存在统一治理检查入口

## 决策日志
- 选择“索引重组”而不是“全量搬迁”，以降低断链风险。
- 增加轻量脚本先覆盖 markdown 路径检查，而不是一开始就做复杂文档 lint。
- 优先增加文件级骨架检查，再逐步升级到签名级检查。
- service 层先只校验文档要求的方法必须存在，额外方法暂不拦截。
- controller 层先只校验主接口路径存在，可选管理接口暂不纳入检查。
- API 合约层先只校验关键字段名和关键返回标记，不做 AST 或序列化级解析。
- 模块边界先只校验顶层包，不立即做更重的依赖分析。
