# 2026-04-21 Opening Report Alignment And Thesis Bridge

## 背景
当前仓库已经建立 harness engineering 风格的文档控制面，但原始开题报告与当前需求层之间仍缺少显式映射。与此同时，论文模板刚被加入仓库，后续 agent 需要有稳定的“模板章节 -> 仓库事实 -> 可写论文文本”桥接能力。

## 目标
- 将开题报告中的核心需求、量化目标、风险信号与导师意见准确沉淀到正式 harness 文档
- 让 `docs/` 能显式回答“哪些需求来自开题报告，哪些文档承载这些需求”
- 读取论文模板后，为 thesis 层建立可导航的章节映射与写作入口
- 增加可复用的 `docx` 文本抽取能力，降低 agent 后续读取学校模板与修改稿的摩擦

## 范围内
- 更新 `docs/00_meta/` 与 `docs/01_planning/` 中与需求翻译直接相关的文档
- 新增 thesis 模板桥接与章节写作辅助文档
- 新增 `docx` 文本抽取脚本或等价能力
- 更新相关索引、prompt shell 或 thesis README

## 范围外
- 修改业务代码或推荐算法
- 引入外部联网依赖安装
- 直接产出最终论文正文定稿

## 输入文档
- `docs/22301095-林乘吉-开题报告.docx`
- `docs/本科毕设论文模板-论文主体.docx`
- `docs/00_meta/topic.md`
- `docs/00_meta/constraints.md`
- `docs/01_planning/project_scope.md`

- `docs/01_planning/acceptance_criteria.md`
- `docs/05_thesis/README.md`
- `docs/05_thesis/thesis_outline.md`

## 执行步骤
1. 从开题报告抽取项目定位、功能模块、量化目标、关键问题、导师意见与进度安排。
2. 对照当前 harness，修正文档失真项并补足来源映射。
3. 读取论文模板，建立章节结构、内容要求与仓库证据的映射。
4. 新增可复用的 `docx` 抽取脚本，供 agent 后续读取模板、批注稿与学校表格。
5. 运行治理检查，确认索引、路径和文档可导航性保持可用。

## 风险
- 若把开题报告中的研究型表述直接当成工程验收，会抬高当前系统的承诺边界。
- 若模板桥接做得过细且不区分“事实层”和“写作层”，容易让 thesis 文档再次膨胀。
- 若新脚本依赖不稳定环境，反而会增加 agent 使用门槛。

## 验收标准
- 仓库内存在可读的“开题报告 -> harness 文档”映射页
- 量化目标、风险与导师意见被准确反映到相应需求层文档
- thesis 层存在“论文模板 -> 章节文件 -> 证据来源”的桥接文档
- 存在可复用的 `docx` 抽取脚本，并能在本机运行
- 相关索引更新后仍可导航，治理检查不因本次改动而退化

## 决策日志
- 2026-04-21：选择补“映射层与桥接层”，而不是重写全部 thesis 草稿，避免过早进入论文大段生成。
