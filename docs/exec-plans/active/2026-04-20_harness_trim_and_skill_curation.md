# 2026-04-20 Harness Trim And Skill Curation

## 背景
当前仓库已经建立 harness engineering 风格的文档控制面，但仍存在可继续收口的地方：部分执行计划状态漂移、可靠性文档轻微重复、论文写作层缺少清晰入口，同时需要从本机 skills 中筛出适合“后端实现 + 论文写作”的组合。

## 目标
- 精简但不破坏当前 harness 导航结构
- 收敛控制面文档的重复与状态漂移
- 明确论文文档层在导航中的使用位置
- 从本机现有 skills 中筛出适合本项目开发和论文写作的组合

## 范围内
- 调整 `docs/` 控制面索引与规范文档
- 整理 `docs/exec-plans/active/` 与 `completed/` 的状态
- 修复已知旧绝对路径引用
- 搜索并推荐本机已安装或已备份的相关 skills

## 范围外
- 大规模重写 numbered docs 设计内容
- 在线安装新的第三方 skills
- 修改业务代码或推荐算法

## 输入文档
- `AGENTS.md`
- `docs/README.md`
- `docs/PLANS.md`
- `docs/RELIABILITY.md`
- `docs/DOCS_OPERATIONS.md`
- `docs/exec-plans/README.md`
- `docs/exec-plans/active/*.md`

## 执行步骤
1. 审阅控制面文档与 active/completed 计划状态，确定精简边界。
2. 合并或降重重复的可靠性文档，并补论文层的导航说明。
3. 调整执行计划索引与归档状态，修复已知旧绝对路径。
4. 搜索本机 skills，筛出适合后端实现、验证、评审与论文写作的组合。
5. 运行治理检查并记录仍存在的缺口。

## 风险
- 归档 active 计划时，若判断失误，可能隐藏仍需持续维护的历史上下文。
- 精简文档时若删掉过多导航，可能降低 agent 的可发现性。

## 验收标准
- 控制面文档重复减少且入口仍清晰可导航
- `active/` 仅保留当前仍在跟进的计划
- 旧绝对路径引用被修正
- 输出一组明确的 skills 推荐，并说明适用场景
- 说明治理检查结果与剩余阻塞

## 决策日志
- 2026-04-20：优先做“收口与降重”，不做大规模目录搬迁，避免新一轮断链。
