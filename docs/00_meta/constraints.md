# Constraints
# 固定约束

## 一、项目边界约束

1. 本项目是工程实践型本科毕业设计，不是科研型算法论文。
2. 推荐对象是“用户”，不是商品、视频或文章。
3. 场景限定为校园社交匹配，重点考虑兴趣、专业、年级、社团等标签信息。
4. 系统以推荐后端为核心，不扩展到复杂即时聊天、完整社区系统、内容平台等大范围业务。

## 二、技术路线约束

1. 后端核心技术栈为 Spring Boot、MyBatis-Plus、MySQL、Redis、Maven、Java 21。
2. 推荐链路固定为：画像 → 召回 → 排序 → 重排 → 解释 → 反馈。
3. 兴趣画像采用改进 TF-IDF 思路，引入时间衰减与 Top-K 筛选机制。
4. 候选召回采用“标签—用户”倒排索引结构。
5. 排序采用余弦相似度计算。
6. 重排采用校园规则约束，如年级差、专业相关性、社团重合度等。
7. 解释必须来源于排序阶段的证据项，不能脱离推荐逻辑单独生成。
8. 反馈更新只能做轻量动态更新，不做复杂在线学习。

## 三、算法与模型约束

1. 不使用深度学习模型作为核心推荐算法。
2. 不引入复杂训练平台，不依赖 GPU 或大规模离线训练流程。
3. 若使用 LLM，其作用仅限于基于证据项的解释文本润色，不参与排序打分与候选选择。
4. 所有算法设计必须优先考虑工程可实现性、可维护性、可验证性。

## 四、论文与实验约束

1. 论文内容必须与系统实际设计和实现一致。
2. 不允许虚构复杂实验数据。
3. 若缺少真实业务数据，可以使用模拟数据，但必须明确标注。
4. 测试结果应围绕功能正确性、推荐合理性、解释一致性、接口可用性展开。
5. 教师已建议进一步明确实验数据来源与评价指标定义，后续所有设计必须对此有明确回应。

## 五、实现风格约束

1. 优先做 MVP（最小可用版本），避免过度设计。
2. 采用单体应用优先，不强行拆微服务。
3. 所有模块职责清晰，命名规范，结构尽量稳定。
4. 所有输出文档必须能够直接服务于后续论文写作与代码实现。
