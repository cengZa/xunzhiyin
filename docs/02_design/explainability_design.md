# Explainability Design
# 内生可解释设计

## 1. 设计目标

确保推荐解释来源于排序与重排过程本身，而不是独立的后验生成逻辑。

## 2. 解释来源

解释只允许来自两类证据：

### 2.1 排序证据
- 共同标签
- 标签权重贡献值
- 共同标签在余弦相似度中的贡献比例

### 2.2 重排证据
- 年级差满足约束
- 专业相关性加权
- 社团重合度加权

## 3. 解释生成流程

1. 从 ranking 阶段获取 contribution_json
2. 选取贡献度最高的 2~3 个标签
3. 从 rerank 阶段获取规则命中情况
4. 组合成结构化 explanation DTO
5. 使用模板生成中文解释文本

## 4. 解释模板示例

### 模板 A：共同兴趣标签
你们都对 {tag1}、{tag2} 有较高兴趣，兴趣画像相似度较高。

### 模板 B：兴趣 + 专业相关
你们在 {tag1}、{tag2} 上兴趣接近，同时专业方向相关，因此匹配度较高。

### 模板 C：兴趣 + 社团
你们在 {tag1} 上偏好接近，并且具有相似的校园组织参与背景。

## 5. 结构化存储格式

evidence_json 示例：
{
  "shared_tags": ["机器学习", "篮球"],
  "tag_contributions": [
    {"tag":"机器学习","score":0.31},
    {"tag":"篮球","score":0.22}
  ],
  "rule_hits": [
    {"rule":"major_related","value":true},
    {"rule":"grade_diff_le_1","value":true}
  ]
}

## 6. 一致性校验

每次生成解释时校验：
1. shared_tags 必须来自排序公共标签集合
2. tag_contributions 必须能映射到计算记录
3. rule_hits 必须来自重排阶段结果
4. reason_text 不得包含 evidence_json 中不存在的事实

## 7. 可选 LLM 使用边界

允许：
- 将结构化证据润色为更自然的中文表达

不允许：
- 新增不存在的推荐理由
- 修改标签贡献排序
- 伪造规则命中信息
- 直接参与排序决策
