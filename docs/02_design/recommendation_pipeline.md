# Recommendation Pipeline
# 推荐链路详细设计

## 1. 设计目标

构建一条面向校园社交匹配场景的结构化推荐链路，使推荐过程可控、可解释、可测试。

## 2. 链路概览

用户标签
→ 改进 TF-IDF 画像构建
→ Top-K 标签提取
→ 倒排索引召回候选用户
→ 余弦相似度排序
→ 校园规则重排
→ 生成解释
→ 返回 Top-K 结果
→ 接收反馈并更新画像

## 3. 画像阶段

### 输入
- 用户基础信息
- 用户标签关系
- 标签类型
- 标签选择时间

### 核心处理
1. 按标签类型构建候选标签集
2. 计算 TF
3. 计算 IDF
4. 加入标签区分度调节
5. 加入时间衰减因子
6. 得到加权标签向量
7. 提取 Top-K 核心标签

### 输出
- 用户画像向量
- Top-K 核心标签

## 4. 召回阶段

### 输入
- 目标用户 Top-K 标签

### 核心处理
1. 读取各标签的倒排索引集合
2. 合并生成候选用户池
3. 去重与过滤
4. 记录公共标签数量

### 输出
- 候选用户列表

## 5. 排序阶段

### 输入
- 目标用户画像向量
- 候选用户画像向量

### 核心处理
1. 对公共标签做向量匹配
2. 计算余弦相似度
3. 记录各标签贡献值

### 输出
- 基础排序分数
- 标签贡献明细

## 6. 重排阶段

### 输入
- 基础排序结果
- 候选用户年级、专业、社团等属性

### 核心处理
1. 年级差规则
2. 专业相关性加权
3. 社团重合度加权
4. 可选轻度多样性约束

### 输出
- 最终排序结果
- 规则命中明细

## 7. 解释阶段

### 输入
- 标签贡献明细
- 规则命中明细

### 核心处理
1. 选取贡献度最高的共同标签
2. 结合命中的校园规则
3. 模板化生成解释文本
4. 可选使用 LLM 做润色，但不得改变证据项

### 输出
- 推荐解释文本
- 证据 JSON

## 8. 反馈阶段

### 输入
- 用户反馈行为

### 核心处理
1. 记录关注/忽略行为
2. 定位该推荐结果的主要证据标签
3. 对相关标签权重做轻量调整
4. 重建或增量更新画像

### 输出
- 更新后的用户画像
- 下一轮推荐使用的新画像

## 9. 指标埋点建议

在链路中记录：
- profile_build_time_ms
- recall_candidate_count
- recall_coverage_estimate
- ranking_time_ms
- rerank_rule_hit_json
- explanation_consistency_flag
- feedback_update_time_ms
- full_pipeline_time_ms
