# 结果分析

## 当前结论
- 项目已经具备可重复的答辩数据、场景化推荐、离线评估和首页演示能力。
- 当前结果更适合“答辩讲解”和“工程验证”，不适合被表述为真实线上效果。
- 新数据集已经能更稳定地展示三类典型场景：
  - 学习搭子
  - 社团搭子
  - 兴趣同频

## 当前演示重点
- 演示用户：`2001`
- 推荐主叙事：
  1. 先基于标签构建画像
  2. 再做候选召回与相似度排序
  3. 再根据场景模式做校园规则重排
  4. 最后用可信连接分抑制资料稀疏的候选人

## 当前观察
- 在 `18` 个用户、`18` 个标签、`86` 条关系的数据规模下：
  - `topK=3` 最适合答辩展示
  - 不同场景模式下的首位和前几位候选更容易发生可解释差异
  - 低可信样本不会仅凭热门标签重合排到最前

## 当前创新点表达
已落地的创新点：
- 不是只做标签重叠推荐
- 在相似度排序之后增加校园场景重排
- 引入轻量可信连接分
- 推荐结果直接返回：
  - `interestScore`
  - `campusScore`
  - `trustScore`
  - `matchedTags`
  - `matchedRules`
  - `trustReasons`

已新增的补强项：
- 轻量探索
  - 仅在 `interest_partner` 模式启用
  - 不破坏前 2 名主结果
  - 用最后 1 个名额保留潜在高质量连接
  - 解释与首页会明确展示探索原因

## 当前限制
- 相关性仍来自代理规则和 mock 数据，不是人工标注或真实行为验证
- 数据规模仍偏小
- 目前更适合展示“设计合理、工程可解释”，不适合声称“推荐效果已接近真实产品”

## 下一步建议
- 若继续提升推荐质量，优先做：
  - 答辩模式收口
  - 探索位权重与触发阈值实验
