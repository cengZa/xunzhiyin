# Mock Data Design

## 1. 目标
为推荐主链路提供一套可重复初始化的答辩数据集，支持：
- 画像构建
- 召回、排序与重排
- 解释与反馈
- 离线评估与场景矩阵导出

## 2. 初始化入口
- `POST /api/admin/mock/init`
- `POST /api/admin/profiles/rebuild-all`
- `POST /api/admin/recall/rebuild-index`

## 3. 当前数据规模
- 用户：18
- 标签：18
- 用户标签关系：86

## 4. 演示主角
- 演示用户：`2001`
- 昵称：`林舟`
- 人设：
  - 计算机方向学生
  - 偏好 Java、Spring、音乐、ACM、羽毛球
  - 目标是在校园内找到既能聊兴趣、又适合线下建立连接的同学

## 5. 典型场景样本
### 学习搭子
重点候选：
- `2002 柏宇`
- `2011 乔溪`
- `2013 苏衡`

适合展示：
- 专业与学习标签重合
- 学习场景下的规则加权
- 高质量技术候选的稳定排序

### 社团搭子
重点候选：
- `2014 唐澈`
- `2009 罗栀`
- `2010 孟夏`

适合展示：
- 学生组织、志愿活动、辩论、运动等校园场景规则
- 跨专业但校园连接强的社团候选人
- 社团模式与默认模式排序差异

### 兴趣同频
重点候选：
- `2015 周霁`
- `2003 陈栀`
- `2006 何川`

适合展示：
- 音乐、摄影、吉他、羽毛球等兴趣重合
- 跨专业兴趣匹配
- 解释结果更偏“共同兴趣”而不是“同专业”

## 6. 可信连接分对照样本
这些用户专门用于展示“可信连接分”为什么存在：
- `2017 魏澄`
  - 标签少
  - 简短 bio
  - 更像“兴趣可能相关，但资料不够完整”的候选人
- `2018 陆闻`
  - 标签少
  - bio 为空
  - 适合作为“热门标签重合但可信度不足”的对照样本

## 7. 设计原则
- 数据集不是随机堆砌，而是围绕答辩场景设计。
- 每种模式至少有 2 到 3 个可直接讲解的重点候选人。
- 保留少量低可信候选人，用于证明可信连接分的必要性。
- `POST /api/admin/mock/init` 会重置这批 mock 用户的标签关系，保证演示结果稳定。

## 8. 当前限制
- 这仍然是小规模答辩数据集，不代表真实校园分布。
- 本地数据库里如果还有非 mock 用户，`rebuild-all` 会一并重建画像。
- 若要获得最稳定的演示结果，应先执行一次 `POST /api/admin/mock/init`。
